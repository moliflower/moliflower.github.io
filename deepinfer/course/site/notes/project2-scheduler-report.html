1. 先写预测

在看参考解之前，记录 max_active=1/2 与 chunk=1/2/4 对长短混合请求的影响。哪些是猜测，哪些由固定 tick 假设保证？

2. 手算与实际快照

粘贴 README 的 A/B/C 案例实际轨迹，核对每轮预算、首输出、结束和补位时间。解释总工作量为何是 prompt+output-1。

3. 一次真实调试

输入、预期、实际、最小复现、原因、修复、回归测试。若首次通过，也请构造并解释能击穿错误实现的反例，不编造调试经历。

4. 实验

运行命令、原始 18 行 CSV 的保存位置。选两组只改变一个参数的配置，对比 TTFT、输出吞吐和请求 goodput。明确所有时间单位为 tick；窗口含空闲；TPOT 单输出排除。

5. 反例与局限

单输出、同时到达、十亿 tick 的空闲、快照别名分别如何检验？为何 TPOT 恒为 1 不能证明真实 GPU 上 chunk size 没影响？尚未接入的 KV 容量、采样、抢占与设备执行会改变什么？

6. 口头验收

用自己的新输入讲解一轮；指出准入、策略、执行、指标各自负责什么。不要用网页完成率代替测试或解释。
